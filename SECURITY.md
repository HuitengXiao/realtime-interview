# Security Policy

## Reporting a vulnerability

Please do not report security vulnerabilities in public issues, pull requests,
or discussions. Instead, contact the project maintainers privately through the
security contact listed in the repository's hosting settings. Include a clear
description, affected component and version or commit, reproduction steps, and
potential impact.

Do not attach credentials, API tokens, session cookies, private keys, real
interview recordings, transcripts, participant information, production logs,
or database exports. Redact reports and use synthetic examples whenever
possible. We will acknowledge the report, investigate it, and coordinate a
fix and disclosure timeline with you.

## Scope

Security reports are especially useful for issues involving authentication,
authorization, organization data isolation, realtime connections, file or
media handling, database access, secret exposure, and third-party AI or speech
service integrations.

If you accidentally expose a secret or real interview data in this repository,
remove public access where possible, rotate or revoke the affected credential,
and report it privately. Removing it only from the latest commit does not
remove it from Git history.
